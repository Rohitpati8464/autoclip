# Code of conduct

## The short version

Be decent. Assume good faith. Critique code, not people.

## What's expected

- **Be direct about technical problems and kind about people.** "This will break on
  Windows because of path escaping" is welcome. "This is obviously wrong" is not.
- **Assume the other person knows something you don't.** Odd-looking code in this
  project is usually working around something specific; ask before declaring it
  wrong.
- **Accept that maintainer time is finite.** An unanswered issue is not a slight.

## What isn't

Harassment, personal attacks, demeaning comments, unwelcome attention, publishing
others' private information, and sustained disruption. Anything that would make a
reasonable person not want to contribute.

## Enforcement

Report problems privately to the maintainer through
[GitHub](https://github.com/artbyjazi). Reports are handled confidentially.

Responses scale with severity: usually a private word, sometimes removed comments,
occasionally a ban. Maintainers who don't follow this themselves should expect the
same treatment, more so rather than less.

## Scope

Applies in project spaces — issues, pull requests, discussions — and when
representing the project publicly.
